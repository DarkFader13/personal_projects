### Dataset Sematic Modelling

Power BI datasets are structured data sources used for reporting and visualization. They can be created by:

- Connecting to external data models (e.g., SQL databases).
- Uploading Power BI Desktop files, Excel workbooks, or CSV files.
- Creating a dataset directly in Power BI Service.
#### Local Datasets

- **Data Control** – Full control, secure but restricted access.
- **Access Speed** – Faster on local devices, no internet dependency.
- **Limited Access** – Difficult for remote teams; requires IT-managed secure access.
- **Scalability Issues** – Limited by hardware storage capacity.

#### Shared Datasets

- **Data Governance** – Centralized control with access permissions.
- **Access Speed** – Dependent on internet connectivity; optimization required.
- **Remote Access** – Enables collaboration and real-time reporting.
- **Scalability** – Cloud-hosted datasets support large-scale data operations.

#### Import Mode

- **Data is copied** from the source into Power BI.
- **Fast performance** as data is stored locally.
- **Requires refresh** to update data.
- **Storage-intensive** for large datasets.

#### Direct-Query Mode

- **Queries the data source directly** instead of importing.
- **No need for refreshes**, always retrieves live data.
- **Slower performance** due to query execution at runtime.
- **Best for large datasets** where import mode is impractical.

#### Dual Mode

- **Combines Import and DirectQuery** for flexibility.
- **Caches frequently used data** while querying less-used data live.
- **Improves performance** without importing all data.

#### Composite Models

- Allows different tables in a dataset to use different storage modes.
- Example:
    - **Product table (small, Excel-based)** → Import Mode.
    - **Sales table (large, SQL-based)** → DirectQuery or Dual Mode.

#### Live Connection

- Directly connects to **datasets in Power BI Service**.
- **Centralized data source** maintains consistency across reports.
- **Security rules can be enforced** for data protection.

#### Managing Data Source Permissions

Power BI enables **data security** through **permission management**. By setting access levels for datasets, organizations can control who has access to sensitive information, ensuring that only authorized personnel can view or modify confidential data.


### Dataflows
#### Overview
- **Collection of Tables:** Dataflows consist of tables with columns and rows, each cell being an entity.
- **Centralized Data:** Allows the application of transformations and refresh schedules directly in Power BI Service.
- **Reusable Logic:** Promotes reuse of data elements, eliminating the need for multiple connections to data sources.

#### Key Features

- **Scalability:** Dataflows scale efficiently, especially with Power BI Premium, for large datasets.
- **Data Sources:** Dataflows can act as sources for both Power BI Service and Power BI Desktop datasets, as well as for other dataflows.
- **Managed via Power BI Service:** Create, edit, and refresh dataflows directly from the workspace.

#### Considerations and Limitations

- **Maximum Depth:** A dataflow can link to up to **32** other dataflows.
- **Power BI Premium Required:** To refresh more than **10 dataflows** in a workspace, a Premium subscription is necessary.
- **Limited Visibility:** Dataflow dependencies are not easily visible, making management challenging.
- **Parameter Editing:** Parameters cannot be edited independently; the entire dataflow must be modified.

### Dataflows vs. Microsoft Dataverse

> **Dataflows** are ideal for organizations needing shared datasets and reusable transformation logic. **Microsoft Dataverse** is more suitable for organizations requiring complex data management, integrations, and real-time data validation.  As a data analyst, consider the organization's data size, complexity, and integration needs when choosing between Dataflows and Dataverse.
#### Microsoft Dataverse

Microsoft Dataverse provides a cloud-based platform for securely storing and managing data, particularly for business applications. It consists of tables with rows and columns, and is designed to support both standard and custom business data.
#### Key Features of Dataverse:

- **Easy Management:** Cloud-based storage with simplified management of both data and metadata.
- **Security:** Role-based security ensures data is accessible only to authorized users.
- **Integration with Dynamics 365:** Seamlessly integrates with Dynamics 365 data, enabling easy extension with Power Apps.
- **Rich Metadata and Business Logic:** Supports data types, relationships, calculated columns, business rules, workflows, and process flows to ensure data quality and consistency.
- **Productivity Tools:** Dataverse integrates with Microsoft Excel for enhanced productivity and data accessibility.

#### Power BI Dataverse Connector

The **Dataverse connector** enables direct access to Dataverse data in Power BI Desktop, allowing users to create reports, dashboards, and share them across platforms. This is ideal for analyzing data from **Dynamics 365** and other Dataverse tables.

#### Key Power BI Integration Tools:

- **Dataverse Connector** (TDS protocol).
- **Common Data Service Connector** (for larger data queries).
- **Dataflows and Templates:** Enables the integration and transformation of large data sets for reporting.
- **Power BI Template Apps** and **Embedding Options** to enhance app integration.

#### Dataflows vs. Dataverse

**Dataflows:**    
- Best for creating reusable transformation logic.
- Suitable for small to medium-sized organizations.
- Acts as a centralized data source for shared reports and datasets within Power BI.
**Dataverse:**
- Suited for large organizations with massive datasets and complex internal or external data updates.
- Supports advanced business logic, data validation, and user interaction via Power Apps.
- Provides a comprehensive solution for building applications and managing complex datasets.

## Cleaning Data

### Inspecting Data for Quality Before Loading into Power BI

> Before loading data into Power BI, it is essential to evaluate whether the data is suitable for analysis. Incorrect data or incompatible formats can lead to wrong conclusions and business decisions. Using **data profiling tools** ensures that the data is ready for transformation and analysis. Regularly auditing and resolving data quality issues is essential for maintaining reliable and accurate analysis.

#### Power BI Data Types

When loading data into Power BI, the system automatically inspects the first 1,000 rows of each table to determine column data types (e.g., numeric, date, text, true/false). While Power BI typically auto-detects data types, it’s important to verify the results in the **Data View** (Table View) of the **Power Query Editor** to avoid issues later, such as errors in **DAX queries** or visualizations.

#### Data Profiling Tools

Power BI provides three main tools to evaluate data quality:

3. **Column Quality:** Shows the percentage of data that is valid, error-prone, or empty.
    - Ideally, you want *100% valid* data.
4. **Column Distribution:** Displays the distribution of values, showing the count of distinct and unique values.
    - **Distinct**: Total count of values (including duplicates and nulls).
    - **Unique**: Count of values that only appear once.
5. **Column Profile:** Provides a more detailed view of statistics for the first 1,000 rows, including:
    - **Row count**: Verifies if all rows are imported correctly.
    - **Min/Max**: Identifies anomalies in numeric data (e.g., values outside the expected range).


### Resolving Data Quality Issues 

>Data-driven organizations rely on high-quality, consistent data to make informed decisions. Poor data quality can lead to mistakes, missed opportunities, and financial or reputational damage. As a data analyst, ensuring that data is accurate, complete, and reliable is critical to supporting effective decision-making.

#### Data Quality

**Data quality** refers to the accuracy, completeness, and reliability of the data. High-quality data is essential for stakeholders to make correct assessments and build effective strategies. 

#### Common Data Quality Issues:

- **Duplicate Entries**
- **Empty or Missing Values**
- **Errors or Invalid Values**
- **Trailing/leading spaces in text**

#### Tools to Resolve Data Quality Issues

Power BI offers tools within the **Power Query Editor** to help resolve data quality issues and inconsistencies. Using **data profiling tools** allows you to identify issues such as invalid values, missing data, and duplicates before loading the data for analysis.

## Transform Data

### Identifying and Transforming Column Data Types

- **Data Types in Power BI**:
    - Power BI automatically assigns data types based on the first 1,000 rows. However, it’s a best practice to verify and adjust data types before finalizing your report.
    - Common data types include **Whole Number**, **Decimal Number**, **Date/Time**, **Text**, and **True/False**.
### Creating Calculated Columns
**Purpose**: Calculated columns allow you to derive new data from existing columns using **DAX** (Data Analysis Expressions). These columns are calculated at the row level and are added to the dataset for use in reports and visualizations.

### Key Benefits of Correct Data Types and Calculated Columns

- **Accurate Data Representation**: Ensures data is stored and used in the correct format, improving the quality of your analysis.
- **Optimized Performance**: Correct data types help improve data processing speed and reduce errors in visualizations.
- **Enhanced User Experience**: Properly formatted data ensures accurate and meaningful insights, allowing users to interact more effectively with the reports.

### Splitting Columns
Power Query offers several techniques to split column data efficiently, helping transform unstructured or compacted data into a usable format. These splitting operations are crucial for data analysts to prepare data for further analysis and visualization.

- **By Delimiter**: When data is concatenated using a specific delimiter (e.g., comma, space, or tab).
- **By Fixed Length**: When data is structured with a consistent character length. (e.g., splitting regional/postal/country codes)
- **By Position**: When data contains more than two parts, each part of which has a known position
- **By Lower to Upper Case**/**By Upper to Lower Case**: When data has mixed case within a single string (e.g., FirstNameLastName -> First Name Last Name)
- **By Digits to Non-digits**: When data contains alphanumeric values that need to be split into numeric and text components (e.g. any values with units attached 5kg, £200)

### Append Queries

Append Queries allow you to combine data from different sources or tables with the same structure into one table. This is useful when dealing with multiple files or datasets with identical column structures.

- The columns in each source must align. If one source has additional columns, those will be filled with **null** values for the rows from sources without that column.

### Merge Queries

Merge Queries combine data from two or more tables based on a common column (e.g., **CustomerID**). This is useful when the data is spread across multiple tables or sources and needs to be aligned.
#### Join Types:

1. **Left Outer Join**: Includes all rows from the left table and matching rows from the right table.
2. **Right Outer Join**: Includes all rows from the right table and matching rows from the left table.
3. **Full Outer Join**: Includes all rows from both tables.
4. **Inner Join**: Only includes matching rows from both tables.
5. **Left Anti Join**: Includes rows from the left table that don’t match the right table.
6. **Right Anti Join**: Includes rows from the right table that don’t match the left table.

### Table Relationships

Table relationships are crucial for structuring data models in Power BI. In short:
- **Primary Key**: Uniquely identifies each row in a table.
- **Foreign Key**: Connects to a primary key in another table, establishing the relationship.

### Cardinality Types

- **One-to-One (1:1)** – Each row in Table A connects to exactly one row in Table B; Both columns contain unique values
- **One-to-Many (1:M) / Many-to-One (M:1)** – A single value in one table relates to multiple values in another; most common in Power BI.
- **Many-to-Many (M:M)** – Both columns contain duplicate values, often used for complex models linking fact or dimension tables.
