## Model Design

### Star and Snowflake Schemas in Power BI
When designing a data schema for analysis, the two most common models are:

- **Star Schema** – A single fact table connected to multiple dimension tables.
- **Snowflake Schema** – A more normalized version where dimension tables are further split into sub-dimensions.

### Structured Tables
**Fact Tables**:
- Store business processes, metrics, and transactional data. 
- Has Primary & Foreign Keys
- Optimise for lowest level of aggregation/highest grain for performance
**Dimension Tables**:
- Store descriptive attributes about the facts
- Only Individual, non-overlapping data elements
- No Foreign keys or Aggregations
- Use for filtering, labelling & grouping
**Factless Table**:
- Fact Table with only foreign keys.
- Used for bridging many to many relationships (Many to Many -> One to Many to One)
- Transactional Fact Table
**Grain**: 
- Dimension of foreign keys
**Cardinality (of column)**: 
- No. of Unique entries

#### Fact Table types (Exactly 3):
- **Transactional**: Record of every entity (Low Grain)
- **Snapshot**: Record for different points in time (Mid Grain)
- **Accumulated**: Record for every process step (High Grain)

#### Table Sub-Types:
- **Consolidated**: Merge of 2 tables
- **Conformed Tables**: 2 tables at a different grain
- **Aggregated**: Table with some level of aggregation
- **Factless**: Fact table with no measures

#### Partitioned-Hybrid Table:
- Composite Fact/Dimension table for Hybrid star-snowflake schema
- Can partition table directly into separate fact & dimension table
- Requires a bridge for each filter for aggregated dimension measure Fact Partition (Foreign IDs, Dates), (Dimensions, Descriptors}

### Role-Playing Dimensions in Business Intelligence

- A single dimension table can relate to multiple fact tables for different purposes.
- Example: A **Date** dimension table can be used for **Order Date**, **Shipping Date**, and **Delivery Date** in a sales model.
- Power BI allows multiple relationships, but only **one can be active at a time**.

#### Managing Role-Playing Dimensions

- **Manual Approach**: Switch active relationships via **Manage Relationships** in Model View.
- **DAX Approach**: Use the `USERELATIONSHIP` function to temporarily activate an inactive relationship in calculations.
- Can only be used inside DAX functions that accept filters.
- Can **nest up to 10** `USERELATIONSHIP` functions in one expression.
- **One-to-One relationships** allow filtering in only one direction; bidirectional filtering requires two `USERELATIONSHIP` calls.
### CALCULATE (DAX)

- `CALCULATE` is the only DAX function that modifies the filter context, allowing dynamic analysis by applying or overriding filters.
- **Alters filter context** by applying new conditions or overriding existing ones.
- Works with functions like `ALL` to remove external filters.
- Requires filters to be based on existing relationships in the data model.
- Enables granular filtering (e.g., by product, region, or salesperson).
- Can combine multiple filters for refined analysis.

### Cross-Filter Direction

- **Single** – Filters propagate in one direction only.
- **Both (Bi-Directional)** – Filters can flow both ways, enabling more flexible analysis.
- Managing Cross-Filter Direction:
	- Can be set manually in **Model View**.
	- **DAX CROSSFILTER** function dynamically changes filter direction for a specific measure, taking arguments for two table columns and the desired filter direction (`None`, `Single`, or `Both`).


## DAX Model Calculations

### Calculated Columns in Power BI
> Calculated columns add new data to a Power BI model using **DAX expressions**, enabling enhanced analysis and reporting. Unlike standard columns, they **derive values from existing data** and consume memory.

#### Key Features
- Created in **Report View, Data View, or Model View**.
- Can combine data from multiple columns or tables.
- Require **DAX formulas** to populate values dynamically.
- Stored at the **data model level**, affecting performance if overused.

#### Benefits
- **Data Transformation** – Enables format changes, calculations, and categorization.
- **Interactive Reports** – Enhances filtering and slicer functionality.
- **Consistency** – Ensures uniform calculations across reports.
- **Complex Analysis** – Supports advanced calculations like time-based metrics and forecasting.

#### Considerations
- Overuse can **increase memory consumption** and slow performance.
- Relationships between tables must be correctly established when referencing data across tables.
- The `RELATED` function is required when accessing columns from a related table.

#### Key Takeaways
- Calculated columns allow for **custom data transformation** within the model.
- Best used for **categorization and static calculations** rather than aggregations.

### Single Aggregation Measure 
Measures are **dynamic calculations** in Power BI that summarize, aggregate, or analyze data without consuming memory. They adapt to applied filters, making them essential for interactive reporting.

Types of Measures:
- **Quick Measures** – Predefined calculations like averages, time intelligence, running totals, and concatenations.
- **Custom Measures** – DAX-based user-defined calculations for advanced analysis.

#### Time intelligence functions 
Time intelligence functions in DAX are designed to simplify **temporal analysis** by allowing comparisons and calculations across time periods. These functions are crucial for uncovering trends, forecasting, and tracking performance over time. Most useful in practice: `DATEADD`, `DATESINPERIOD`, `EOMOTH`
#### Types of Measures

**Additive Measures**
- Can be summed across any dimension without losing meaning.
- Useful for simple aggregations like total sales or quantities.
- Examples include total sales, total quantities, or any data that can be summed directly.

**Semi-Additive Measures**
- Can be summed across some dimensions but not all.
- Typically used for time-sensitive data like inventory.
- Requires functions like `LASTDATE` to accurately calculate totals for certain dimensions (e.g., inventory balances at the end of a period).

**Non-Additive Measures**
- Cannot be summed across any dimension.
- Used for ratios or percentages, such as profit margins.
- Requires DAX functions like `AVERAGEX`, `SUMX`, and `DIVIDE` to properly calculate meaningful results.

### PATH Function

- The **PATH** function creates hierarchical structures from data, turning complex relationships into clear paths.
- It helps visualize data structures like organizational charts or product hierarchies, making connections easier to understand.

#### PATHCONTAINS Function

- **PATHCONTAINS** checks if specific items exist within a hierarchy.
- It helps filter and segment data, enabling precise analysis.`

#### PATHITEM Function

- The **PATHITEM** function extracts specific layers of hierarchical data, which aids in detailed analysis.

#### PATHITEMREVERSE Function

- **PATHITEMREVERSE** traces data paths backward, helping to understand how individual elements fit into larger structures.`

#### PATHLENGTH Function

- **PATHLENGTH** measures the depth of hierarchical structures, showing how extensive or complex a hierarchy is.
- It helps analyze things like product ranges or organizational charts, providing insights into the number of levels in a hierarchy.

## Implementing Data Model#

### Calculated Tables

**Cloning Tables**    
- When you need to manipulate data without affecting the original table, create a cloned version using the `ALL` function.
- Example: `Sales (Cloned) = ALL ('Sales')`
**Combining Data from Multiple Sources**    
- Use calculated tables to merge data from different sources (e.g., combining product categories with sales data for better comparison).
- Example: Merging sales and product tables for cross-category analysis.
**Normalizing Dimension Tables**    
- Break down data in tables, such as creating a snowflake dimension, to separate related information for easier analysis.
- Example: Splitting product categories and subcategories into different tables for better clarity.
**Combining Tables with Similar Structure**    
- Combine tables with similar structures (e.g., Eastern and Western customer tables) into one unified table.
- Example: Merging customer data from different regions into a single customer table.
**Using Measures to Create Calculated Tables**    
- Create calculated tables using measures, which allow for summarization and visualization of large datasets.
- Example: Create a table that displays individual sales by country based on the "Sales" measure.
- Example formula:  
    `Country Sales = SUMMARIZE('Sales', 'Sales'[Country], "Total Sales", [Sales])`

### Data Hierarchy
- A hierarchy is a structured relationship between data attributes, ranked from high-level overviews to granular details.
- In Power BI, hierarchies allow users to drill down from parent levels to child levels, improving data exploration.
- Examples include time-based hierarchies (Year > Quarter > Month > Day) or location-based hierarchies (Country > State > City).
- You can add up to five levels in a hierarchy.

#### Creating Hierarchies in Power BI
- **Geographical Hierarchy**: Create a hierarchy for location data, such as country, state, city, and postal code.
    - Format fields like "Country", "State", and "City" with the appropriate data category (e.g., "Country" as "Country").
    - Create a hierarchical structure using fields and visualize the data in a column chart or map.

#### Drill-Down Functionality
- In visualizations, enable drill-down functionality by adding levels of the hierarchy to the x-axis.
- Power BI displays arrows indicating available drill-down levels, allowing users to navigate through the data (e.g., drill down from country to state or city).
- Use the **Drill Down icon** to move between hierarchy levels interactively.

#### Creating and Managing Hierarchies
- In the **Data Pane**, create a new hierarchy by selecting the relevant field and choosing **Create Hierarchy**.
- Add fields (e.g., state, city) to the hierarchy by selecting **Add to Hierarchy** and specifying the hierarchy to add it to.

#### Using PATH DAX Function for Hierarchies
- The **PATH** DAX function can help analyze organizational or geographical hierarchies by calculating the path length, useful for reporting structures or product categories.

## Optimise Model Performance 

### Performance Analyzer
- **Evaluate Report Performance**: It helps you diagnose slow-running reports, pinpoint inefficient components, and optimize them for faster performance.
- **Analyze Visual Renderings**: It helps identify slow-rendering visuals and allows you to optimize them for quicker loading times.
- **Data Model Insights**: Offers insights into how the data model impacts report performance, guiding you in maintaining and improving the model's efficiency.

####  Real-World Applications

- **Optimizing Large Datasets**: When working with large datasets, use the Performance Analyzer to ensure reports remain responsive by identifying slow-performing elements.
- **Complex Data Models**: Analyze and maintain the efficiency of data models, particularly when dealing with complex relationships and calculations.
- **Fine-Tuning Reports**: Use the Performance Analyzer to identify and optimize slow visuals, queries, and data model components, improving overall report performance.
### Report Performance 
#### Reducing Cardinality
- **Cardinality** refers to the uniqueness of data in a column. Reducing cardinality can improve performance by minimizing the number of unique values Power BI has to process.

#### Aggregation and Summarization
- **Aggregation** involves summarizing large volumes of detailed data into more manageable summary tables, which improves query performance by reducing the amount of data Power BI processes.

#### Benefits of Aggregations
- **Improved Query Performance**: Pre-calculated aggregates reduce the volume of data being processed, improving query speed.
- **Faster Report Refreshes**: Smaller, aggregated tables refresh faster than large datasets, leading to reduced refresh times.
- **Scalability**: Aggregations can help manage growing data volumes, such as when expanding to new regions or adding products to the inventory.
